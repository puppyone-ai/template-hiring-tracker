# 公开模板维护规范

## 可发布的内容

- 目录、字段、状态机和通用工作流。
- 重写后的岗位、邮件、面试和记录模板。
- 独立编写且明确标注虚构的演示人员、经历、日期及流程结果。
- 邮箱和网址示例使用 `example.com`；公司、地点、薪酬、联系人及正式条款使用 `{{...}}` 占位符。

## 私有内容的处理

真实简历、作品集、照片、联系方式、平台卡片与 ID、邮件原文、面试评价、薪酬、地址、内部预约或入职链接、发送 payload、自动化日志及本机路径均留在私有工作区。不要将它们复制到公开仓库后再逐项打码。

**只替换姓名不够。** 学校、工作经历、项目描述、时间线、评价措辞与附件名的组合仍可能识别具体人员。公开示例不与任何真人一一对应，需重新编写这些字段；无法判断是否可公开的内容不纳入模板。

私有仓库的 `.git`、提交记录、分支、标签、issue 内容及远程配置不导入模板仓库。公开 PR 的标题、描述、截图、日志也不得包含这些信息。

## 发布前检查

1. 查看 `git status --short`、暂存文件列表和完整暂存 diff，确认只有预期模板文件。
2. 检查文件名、正文、CSV、HTML、链接、图片、附件及元数据；不发布真实材料或渠道导出。
3. 检查 email、电话、平台 ID、外部 URL、绝对路径、公司人员信息和内部条款。公共说明中的示例地址必须属于保留示例域名。
4. 检查拟推送提交及其历史，确保敏感内容没有出现在任何提交中；删除工作区文件不能清除已提交的内容。
5. 运行 `python3 scripts/build_console.py --check` 与 `git diff --check`，确认表格、目录、链接和 HTML 一致。
6. 仅发布虚构模板的最终内容。发现真实资料已被公开时，停止继续发布并通知仓库维护人处理。

`.gitignore` 和脚本均不能保证识别所有敏感信息，尤其无法识别所有人物经历和间接身份线索。人工审阅仍是必要步骤。
