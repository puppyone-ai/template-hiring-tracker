# 字段与状态规范

## 三张表

- 当前表：`00-console/候选人总表.csv`，当前阶段与人工结论的唯一事实来源。
- 归档表：`90-archive/候选人归档表.csv`，阶段固定为 `已归档`。
- 已入职表：`91-hired/已入职表.csv`，阶段和人工结论均为 `已入职`。
- HTML 只展示当前表。所有 CSV 使用 UTF-8 和相同列顺序。

```text
序号,候选人ID,姓名,岗位,学校,来源,入库时间,当前阶段,人工结论,AI建议,岗位ID,候选人目录,最后更新
```

| 字段 | 维护约定 |
| --- | --- |
| 序号 | 每张表内从 1 连续编号，不是稳定 ID |
| 候选人ID | `C-YYYYMM-NNN`，跨当前、归档、已入职三表唯一且永久保留 |
| 姓名 | 可靠来源确认；模板使用“示例候选人甲”等明确虚构称呼 |
| 岗位 | 与岗位卡的岗位名称、活跃目录中间层完全一致 |
| 学校 | 只记录可核实信息，未知写待核实；示例为虚构机构 |
| 来源 | 示例使用“示例投递”“示例内推”；实际来源由私有工作区另行定义 |
| 入库时间 | `YYYY-MM-DD`，首次建档后不改动 |
| 当前阶段 | 下方受控值，真实变更需人工确认 |
| 人工结论 | 可为空，必须由人工确认；模板中的非空值均为虚构演示 |
| AI建议 | 明确标为 `AI建议：...`，不能代替人工结论 |
| 岗位ID | `J-YYYYMM-缩写`，必须有对应岗位卡 |
| 候选人目录 | 从仓库根目录起算的相对路径，无本机绝对路径 |
| 最后更新 | `YYYY-MM-DD`，最近一次有效更新日期 |

## 受控值

当前阶段：`待确认`、`新收到`、`待初筛`、`待约一面`、`一面`、`待约二面`、`二面`、`待约三面`、`三面`、`待决策`、`Offer沟通`、`待入职`、`已入职`、`暂停`、`已结束`、`已归档`。

人工结论：空值、`继续推进`、`pass`、`淘汰`、`候选人退出`、`Offer拒绝`、`Offer接受`、`已入职`。

`pass` 在本模板中表示**不继续推进**，不表示通过。遇到口语表达不明确时，先向人工核实。

归档表人工结论限 `pass`、`淘汰`、`候选人退出`、`Offer拒绝`；已入职表只使用 `已入职`。其余待确认情形留在当前表，不能自行结束流程。

## 排序和关联

三个表均按岗位 ID 分组，同组内按候选人 ID 排序，组间保留一个空行。空行不计入候选人数量。

示例固定使用 `2030-01`，只表达流程先后，并非当前招聘。新建私有工作区时按实际建档月份分配 ID，同时检查全部三张表。
